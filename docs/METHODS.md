# Measurement method and evidence boundaries

## Frozen workload and counts

- Main: input lengths 2,048 / 8,192 / 32,768 / 65,536 / 100,000 / 200,000; total concurrency 1 / 2 / 4 / 6 / 8; code and prose suffixes; three repetitions. Exactly 180 waves and 756 requests.
- Foreground load: background input lengths 8,192 and 100,000; total concurrency 1 / 2 / 4 / 6 / 8; three repetitions. One foreground probe per wave has 2,048 input tokens and a 128-token output cap; backgrounds have 1,024-token caps. Exactly 30 waves and 126 requests. The probe starts 0.5s after the background send barrier. C=1 has no background.
- Original soak: unqualified, retained separately. 900s admission /937.10s with 96 code-only requests; client peak 8, native peak 9 in 182/1863samples. It does not count as a qualified mixed isolated8-way soak.
- Corrective soak v2: separate source/protocol and changed backend-aware admission pacing,900s admission then drain to 914.40s, 90 requests, code 46/prose 44, both classes at all 4 lengths. Observed native/client peak 8, no excess or unknown samples across 1818 probes, zero request errors/cache/retractions. Never pool with v1 as identical-policy throughput.
- Excluded warmups/pilots: 6 waves, 17 requests. These remain in the observation export under phase=pilot, with kind distinguishing warmups from pilots, but never enter the main matrix.

The model receives exact input token IDs generated by its tokenizer/reference encoder. Authored repeated reference notes fill the requested input length; this is synthetic prefill, not representative natural-document text. The code suffix requests a Python LRU cache and examples; the prose suffix requests an explanatory chapter. A literal assistant role marker and thinking boundary suppress thinking in the prompt. Native reasoning-token counters were zero; that counter is not an independent semantic classification of every generated token.

Each request has a deterministic unique early prefix in a phase-specific namespace. Exact payload bytes are serialized, hashed and persisted before the wave clock and send barrier. Temperature is zero and EOS is not ignored. All main outputs reached the 1,024-token cap, all foreground probes reached 128, and all soak outputs reached 256. Completion means a terminal native response, not a correct or useful completed program.

## Metrics

- **TTFT:** first observed output token minus that request's send start. Includes API admission/queueing and prefill; it is not an isolated GPU phase timing.
- **Decode-window rate:** `512 / (t641 - t129)` using the first native cumulative-output event at or above each threshold. Speculative bursts can cross thresholds; this is the exact emitted-window definition, not internally interpolated per-token kernel timing. Window values exist for every main output; the 128/256-token phases intentionally have no such window.
- **Main decode cell:** median of the three wave medians. Each wave median is over its requests. This is not a peak or a minimum.
- **Actual batch output throughput:** sum of actual generated output tokens divided by elapsed time from first request send to last request finish. Includes prefill, queuing and observed pauses. Cell summaries are the median across three waves. Never derive this by multiplying median decode speed by concurrency.
- **Effective prefill:** total prompt tokens divided by elapsed time until the last request's first token. It can include queueing and mixed decode work and is not a dedicated kernel benchmark.
- **Maximum token gap:** maximum elapsed time between successive events with an increased cumulative output-token count. Repeated-count or keepalive events do not hide a no-token gap. Table p95 is the interpolated descriptive percentile over per-request maxima in that cell, not the single largest stall and not a population SLA.
- **Latency distributions:** request-level p50/p95 on successful responses, with errors retained separately. Each foreground condition has only three probes. Main cells have three waves and `3*C` requests. Mean, sample SD and range of wave aggregate throughput are included in CSV.

## Validation and isolation

The saved source/protocol identities were fixed before measured inference. Exact payload hashes/input lengths/output budgets and all native prompt/completion counts were checked for 1,085 unique retained requests. Offline replay of 281,078 native SSE JSON frames reproduced every saved final output-ID list, terminal reason and native count. The public export retains event times/counts and selected native counters, not full IDs/text/bodies; replay of raw ID content was a private validation step.

Native cached-token counters were zero for every recorded request. The main matrix had no observed backend-load envelope excess and no failed load samples; requests were never silently retried. This is evidence of controlled scheduled load, not a mathematical proof no external client existed. The backend load sampler interval was 0.5s. The pre-existing periodic generation watchdog and relevant scheduled inference producers were held temporarily and restored; production runtime flags, weights and precision were not changed.

Across 448 periodic observations all eight serving instances remained unchanged and no OOM flag was observed. Minimum sampled host MemAvailable was 29.14GiB. A sampled floor is detection, not guaranteed instantaneous containment. Models, NFS and fallback were retained; return-control inference was verified after cleanup.

Some live status counters were not maintained consistently by the collector. Final totals are reconstructed from immutable per-request/wave records, payloads and raw responses, not those counters. This bookkeeping limitation was recorded without editing the frozen collector during inference.

## What is not established

No code correctness, full-agent task completion rate, long-term reliability guarantee, energy efficiency, 16/32-way performance, full-1M retrieval quality or clean-machine reproduction is claimed. Prefix-reusing agent histories were not exercised by this deliberately cold-prefill workload. Native request concurrency and a safe autonomous-worker pool size are not identical. GPU/network phase profiling was not performed, so delivery stalls must not be assigned to a specific kernel or network component from this study alone.

The separately qualified up-to-eight-way corrective soak is a bounded stability observation, not a six-hour continuously saturated eight-user soak. The overall study occupied about six hours, but most of that time was sequential waves at varied concurrency.
